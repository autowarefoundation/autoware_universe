# autoware_candidate_bank

## Purpose

`autoware_candidate_bank` keeps candidate trajectories generated by the DiffusionPlanner across generations, re-evaluates them against the latest ego and environment state, and selects one of them.
The selected trajectory is passed to the downstream planning chain. The node never generates a new trajectory.

```text
DiffusionPlanner
  -> candidate_bank_node
  -> TrajectoryModifier
  -> TrajectorySelector / PlanningValidator
  -> /planning/trajectory
```

In `autoware_launch`, the node is inserted between the DiffusionPlanner and the trajectory modifier by `e2e_components/diffusion_planner.launch.xml` (`enable_candidate_bank:=true`).

## Inner-workings / Algorithms

### Decision trigger and buffering

- Each `CandidateTrajectories` message is the decision trigger.
- Odometry, tracked objects, predicted objects and traffic signals are stored in bounded timestamp buffers.
- Candidates and `PredictedObjects` are associated by exact equality of the generation `header.stamp`.
- The evaluation time is the latest `Odometry.header.stamp` available at the trajectory callback.
- If no exact pair is ready, the last selected trajectory is republished within `output.hold_last_selected_sec`.
- When no candidate can be selected, the raw DiffusionPlanner trajectory is not passed through (`output.no_selection: suppress`).

### Bank lifecycle

1. **add**: store the new generation of candidates.
2. **purge**: drop candidates that are too old or no longer projectable onto the current ego pose.
3. **evaluate**: update the live suffix from the current ego position and evaluate
   - static and dynamic object safety,
   - cross-collision between candidates and predicted objects,
   - map and traffic rule context (traffic signals, lane boundaries),
   - progress, route deviation, clearance and comfort costs.
4. **select**: choose one candidate using safety tiers and hysteresis.
5. **publish**: output the selected `Trajectory` and `CandidateTrajectories`.

The route or map update resets the bank.

## Inputs / Outputs

### Input

| Name                        | Type                                                        | Description                                                 |
| --------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------- |
| `~/input/trajectories`      | `autoware_internal_planning_msgs/msg/CandidateTrajectories` | raw candidates from the DiffusionPlanner (decision trigger) |
| `~/input/predicted_objects` | `autoware_perception_msgs/msg/PredictedObjects`             | predictions associated with each candidate generation       |
| `~/input/odometry`          | `nav_msgs/msg/Odometry`                                     | ego state and evaluation time                               |
| `~/input/tracked_objects`   | `autoware_perception_msgs/msg/TrackedObjects`               | current object observations                                 |
| `~/input/route`             | `autoware_planning_msgs/msg/LaneletRoute`                   | route context (transient local, resets the bank on update)  |
| `~/input/vector_map`        | `autoware_map_msgs/msg/LaneletMapBin`                       | map context (transient local, resets the bank on update)    |
| `~/input/traffic_signals`   | `autoware_perception_msgs/msg/TrafficLightGroupArray`       | traffic signal context                                      |

### Output

| Name                    | Type                                                        | Description                                                        |
| ----------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------ |
| `~/output/trajectory`   | `autoware_planning_msgs/msg/Trajectory`                     | selected trajectory                                                |
| `~/output/trajectories` | `autoware_internal_planning_msgs/msg/CandidateTrajectories` | selected trajectory as a single candidate                          |
| `~/debug/status`        | `std_msgs/msg/String`                                       | JSON status (state, counters, selection result)                    |
| `~/debug/markers`       | `visualization_msgs/msg/MarkerArray`                        | RViz markers (when `debug.publish_markers` is true)                |
| `~/debug/cross_matrix`  | `std_msgs/msg/String`                                       | cross-collision matrix JSON (when `debug.publish_markers` is true) |

### Service

| Name      | Type                   | Description                    |
| --------- | ---------------------- | ------------------------------ |
| `~/reset` | `std_srvs/srv/Trigger` | reset the bank and its context |

## Parameters

The default parameters are in [config/candidate_bank.param.yaml](config/candidate_bank.param.yaml).
Most parameters are read at startup, so the node has to be restarted after changing them.

## Launch

```bash
ros2 launch autoware_candidate_bank candidate_bank.launch.xml
```

## Tools

The following offline analysis scripts are installed to `lib/autoware_candidate_bank`.

| Script                                     | Description                                               |
| ------------------------------------------ | --------------------------------------------------------- |
| `inspect_graph.py`                         | inspect the live topic wiring around the node             |
| `analyze_candidate_bank_internal_log.py`   | analyze the internal debug event log                      |
| `analyze_static_clearance.py`              | visualize static-clearance decisions                      |
| `plot_candidate_cross_collision_matrix.py` | plot a cross-collision matrix from `~/debug/cross_matrix` |

## Assumptions / Known limits

- The bank only selects among trajectories given by the DiffusionPlanner.
- Parts of the implementation are adapted from `autoware_diffusion_planner`. The source mapping is recorded in [UPSTREAM_FILES.json](UPSTREAM_FILES.json).
